# AraChat Web/v1 — Web Core: проектирование и дизайн

## 1. Цель Web Core

**Web Core** — первая функциональная веха веб-версии **AraChat Web/v1**. Её цель — создать базовый рабочий фундамент AraChat, на котором дальше будут строиться групповые чаты, каналы, вложения, голосовые сообщения, звонки, семейный режим, E2EE и остальные функции первого публичного релиза.

Web Core должен дать пользователю возможность:

- зарегистрироваться через Telegram Login Widget;
- получить постоянный 16-значный AraChat ID;
- выбрать username;
- задать пароль;
- создать PIN/код доступа для быстрого входа на доверенном устройстве;
- получить резервный код восстановления;
- войти по AraChat ID и паролю;
- войти через Telegram, если Telegram уже привязан к аккаунту;
- быстро войти по PIN на доверенном устройстве;
- посмотреть и отредактировать базовый профиль;
- выбрать русский или английский язык интерфейса;
- увидеть список личных чатов;
- открыть личный чат 1-на-1;
- отправить и получить текстовое сообщение;
- синхронизировать базовые изменения между устройствами через WebSocket;
- увидеть активные устройства и историю входов.

## 2. Границы Web Core

### 2.1 Входит в Web Core

1. Базовая веб-оболочка приложения.
2. Регистрация через Telegram Login Widget.
3. Создание аккаунта и выдача AraChat ID.
4. Выбор username.
5. Создание пароля.
6. Создание PIN/кода доступа для доверенного устройства.
7. Выдача резервного кода восстановления.
8. Вход по AraChat ID + пароль.
9. Вход через Telegram для уже привязанного аккаунта.
10. Быстрый вход по PIN на доверенном устройстве.
11. Восстановление через резервный код.
12. Заявка на ручное восстановление через Telegram-бот.
13. Базовый профиль пользователя.
14. 20 встроенных аватарок с животными, людьми и роботами.
15. Настройка языка RU/EN.
16. Настройка публичного отображения номера телефона.
17. Список личных чатов.
18. Личный чат 1-на-1.
19. Текстовые сообщения.
20. Базовые статусы доставки на уровне технического подтверждения.
21. WebSocket-подключение.
22. Базовая синхронизация между устройствами.
23. Активные устройства.
24. История входов.
25. Базовый аудит действий безопасности.

### 2.2 Не входит в Web Core

Следующие функции не проектируются как часть Web Core, но Web Core должен не мешать их дальнейшему добавлению:

- групповые чаты;
- каналы;
- голосовые сообщения;
- фото, видео, документы и другие файлы;
- реакции;
- смайлики;
- typing-индикаторы;
- расширенный presence: в сети, не в сети, был недавно;
- семейный режим;
- детские аккаунты;
- родительский доступ;
- жалобы и модерация;
- аудиозвонки;
- демонстрация экрана;
- полная реализация E2EE;
- удаление сообщений с месячным восстановлением;
- Desktop и Mobile клиенты.

### 2.3 Важное архитектурное ограничение

Web Core не должен закрывать путь к будущему E2EE. Даже если полная криптографическая реализация будет вынесена в веху **Web Security & Family**, модель сообщений и API должны быть готовы к хранению зашифрованного payload.

Решение для Web Core:

- в API и БД использовать нейтральное поле `payload` / `encrypted_payload`;
- не привязывать бизнес-логику к открытому тексту сообщения;
- не проектировать поиск по содержимому сообщений как обязательную функцию Web Core;
- не строить модерацию личных сообщений через скрытое чтение сервером.

## 3. Пользовательские сценарии

### 3.1 Первый запуск

1. Пользователь открывает веб-приложение.
2. Приложение определяет язык браузера.
3. Если язык русский или английский — выбирает соответствующую локаль.
4. Если язык другой — по умолчанию используется английский или русский по продуктовому решению.
5. Пользователь видит стартовый экран AraChat.
6. Пользователь выбирает:
   - зарегистрироваться через Telegram;
   - войти по AraChat ID и паролю;
   - восстановить доступ.

### 3.2 Регистрация нового пользователя через Telegram

1. Пользователь нажимает “Продолжить через Telegram”.
2. Открывается Telegram Login Widget.
3. Backend проверяет подпись Telegram.
4. Если Telegram identity уже привязан к аккаунту, пользователь входит в существующий аккаунт.
5. Если Telegram identity не найден, создаётся новый пользователь.
6. Система генерирует уникальный 16-значный AraChat ID.
7. Пользователь выбирает username.
8. Пользователь задаёт пароль.
9. Пользователь может создать PIN/код доступа для текущего доверенного устройства или пропустить этот шаг.
10. Если пользователь пропускает PIN, быстрый вход на этом устройстве не включается, но PIN можно добавить позже в настройках.
11. Система показывает резервный код восстановления.
12. Пользователь подтверждает, что сохранил резервный код.
13. Пользователь попадает в приложение.

### 3.3 Вход зарегистрированного пользователя

Основной сценарий:

1. Пользователь вводит AraChat ID.
2. Пользователь вводит пароль.
3. Backend проверяет данные.
4. Если вход успешен, создаётся сессия.
5. В LoginHistory пишется запись о входе.
6. Пользователь попадает в приложение.

Дополнительный сценарий:

1. Пользователь выбирает “Войти через Telegram”.
2. Backend проверяет Telegram Login Widget.
3. Если Telegram identity привязан к AraChat ID, пользователь входит.
4. Если Telegram identity не привязан, приложение предлагает регистрацию нового аккаунта.

### 3.4 Быстрый вход по PIN

1. Пользователь открывает приложение на доверенном устройстве.
2. Приложение видит действующее доверие устройства.
3. Пользователь вводит PIN/код доступа.
4. Если PIN корректен, создаётся или продлевается сессия.
5. Если PIN введён неверно 5 раз, PIN на этом устройстве блокируется.
6. После блокировки нужен вход по AraChat ID + пароль или Telegram.

Правила PIN:

- длина от 4 до 8 цифр;
- 5 попыток;
- срок доверия устройства — 1 год;
- PIN действует только на конкретном доверенном устройстве;
- PIN не является способом восстановления аккаунта.

### 3.5 Восстановление через резервный код

1. Пользователь выбирает “Восстановить доступ”.
2. Вводит AraChat ID.
3. Вводит резервный код восстановления.
4. Backend проверяет хеш кода.
5. Если код корректен, пользователь задаёт новый пароль.
6. Старый резервный код отзывается.
7. Пользователь получает новый резервный код.
8. Событие записывается в AuditLog.

Правила резервного кода:

- 24 символа;
- группы по 4 символа;
- только латинские буквы верхнего регистра и цифры;
- исключены `0`, `O`, `1`, `I`;
- сервер хранит только хеш;
- после 5 неудачных попыток восстановление через код временно блокируется.

### 3.6 Ручное восстановление через Telegram-бот

1. Пользователь пишет в официальный Telegram-бот восстановления.
2. Бот просит указать AraChat ID.
3. Бот фиксирует Telegram user ID, username Telegram, request id и время обращения.
4. Бот создаёт заявку `TelegramRecoveryRequest`.
5. Админ-панель показывает заявку владельцу проекта.
6. Если Telegram identity из заявки совпадает с Telegram identity, привязанной к AraChat ID, администратор запускает одноразовую процедуру сброса.
7. Пользователь задаёт новый пароль.
8. Пользователь получает новый резервный код восстановления.
9. Все действия записываются в AuditLog.

Так как регистрация в AraChat Web/v1 выполняется через Telegram Login Widget, у аккаунта должен быть привязанный Telegram identity. Если Telegram identity из заявки не совпадает с Telegram identity аккаунта, восстановление в Web Core не выполняется. Заявка может быть сохранена для аудита и ручного анализа, но администратор не должен выдавать доступ без совпадения Telegram identity.

### 3.7 Первый личный чат

1. Пользователь открывает главный экран.
2. Пользователь видит список чатов.
3. Если чатов нет, показывается пустое состояние.
4. Пользователь ищет другого пользователя по username или напрямую вводит AraChat ID.
5. Открывается личный чат 1-на-1.
6. Пользователь отправляет текстовое сообщение.
7. Сообщение сохраняется на сервере.
8. Получатель получает событие через WebSocket, если он онлайн.
9. Оба устройства отправителя синхронизируются.

## 4. Экраны Web Core

### 4.1 Стартовый экран

Назначение: объяснить, что такое AraChat, и предложить вход или регистрацию.

Элементы:

- логотип AraChat;
- короткий слоган;
- кнопка “Продолжить через Telegram”;
- кнопка “Войти по AraChat ID”;
- ссылка “Восстановить доступ”;
- переключатель языка RU/EN.

### 4.2 Экран Telegram-регистрации

Элементы:

- Telegram Login Widget;
- пояснение, что номер телефона не передаётся в AraChat как обязательный идентификатор;
- сообщение об ошибке при неуспешной проверке Telegram подписи.

### 4.3 Экран выбора username

Элементы:

- поле username;
- проверка доступности;
- подсказки по допустимым символам;
- состояние “username занят”;
- кнопка продолжения.

Правила:

- username уникален;
- длина username — от 3 символов;
- разрешены только латинские буквы и цифры `0–9`;
- запрещены маты, оскорбительные слова и любой 18+ контент;
- username может изменяться сколько угодно раз в неделю, но не более 3 раз за день;
- username не заменяет AraChat ID.

### 4.4 Экран создания пароля

Элементы:

- поле пароля;
- повтор пароля;
- подсказка “от 5 до 30 символов”;
- индикатор минимальной сложности;
- предупреждение о безопасности;
- кнопка продолжения.

Правила пароля:

- длина от 5 до 30 символов;
- разрешены латинские буквы в нижнем и верхнем регистре;
- разрешены цифры `0–9`;
- пробелы и спецсимволы в Web Core не используются, если не будет принято отдельное решение.

### 4.5 Экран создания PIN/кода доступа

Элементы:

- поле PIN;
- повтор PIN;
- подсказка “от 4 до 8 цифр”;
- пояснение, что PIN действует только на этом устройстве;
- возможность пропустить создание PIN.

Решение для Web Core: PIN можно пропустить при создании профиля. Если пользователь пропускает PIN, быстрый вход на этом устройстве не включается. Добавить PIN можно позже в настройках.

### 4.6 Экран резервного кода восстановления

Элементы:

- резервный код восстановления;
- кнопка копирования;
- кнопка “Я сохранил код”;
- предупреждение, что код показывается один раз;
- запрет перехода дальше без подтверждения сохранения.

### 4.7 Экран входа по AraChat ID и паролю

Элементы:

- поле AraChat ID;
- поле пароля;
- кнопка входа;
- ссылка “Войти через Telegram”;
- ссылка “Восстановить доступ”;
- ошибки неверных данных и превышения попыток.

### 4.8 Экран быстрого входа по PIN

Элементы:

- приветствие пользователя;
- поле PIN;
- счётчик оставшихся попыток;
- кнопка “Войти другим способом”.

### 4.9 Главный экран приложения

Desktop/tablet layout:

- левая колонка: список чатов;
- центральная область: выбранный чат или пустое состояние;
- верхняя панель: профиль, настройки, язык/статус подключения.

Mobile layout:

- экран списка чатов;
- экран выбранного чата отдельным переходом;
- нижняя или верхняя навигация уточняется на этапе UI.

### 4.10 Список чатов

Элементы:

- список личных чатов;
- поиск по username;
- прямой ввод AraChat ID для создания личного чата;
- пустое состояние;
- индикатор последнего сообщения;
- базовый индикатор непрочитанных сообщений, если будет готов в Web Core.

### 4.11 Личный чат

Элементы:

- заголовок чата;
- сообщения;
- поле ввода;
- кнопка отправки;
- состояние отправки;
- состояние ошибки отправки;
- автопрокрутка к новым сообщениям.

### 4.12 Профиль

Элементы:

- аватар;
- display name;
- username;
- AraChat ID;
- необязательный номер телефона;
- настройка публичного отображения номера телефона;
- язык интерфейса;
- тема дизайна: AraChat Halo, AraChat Orbit или AraChat Aurora.

AraChat ID показывается только в профиле, чтобы не перегружать главный экран. На главном экране AraChat ID не отображается постоянно.

Аватары в Web Core:

- доступно 20 встроенных аватаров;
- категории: животные, люди и роботы;
- загрузка собственной аватарки не входит в Web Core и переносится на следующую функциональную веху.

### 4.13 Настройки безопасности

Элементы:

- смена пароля;
- регенерация резервного кода;
- управление PIN;
- список активных устройств;
- история входов;
- завершение сессий.

### 4.14 Настройки внешнего вида

Элементы:

- выбор темы дизайна;
- тема по умолчанию: AraChat Halo;
- альтернативные темы: AraChat Orbit и AraChat Aurora;
- preview-карточка выбранной темы;
- сохранение выбранной темы в профиле пользователя;
- применение темы без перезагрузки страницы.

## 5. UX-логика

### 5.1 Принципы UX для Web Core

1. Пользователь не должен видеть техническую сложность регистрации.
2. AraChat ID нужно показать явно и объяснить, что он постоянный.
3. Резервный код восстановления нужно объяснить простым языком.
4. PIN нельзя подавать как “пароль от аккаунта”; это быстрый вход на устройстве.
5. Ошибки должны быть понятными и локализованными.
6. Потеря доступа должна объясняться честно: без пароля, Telegram и резервного кода восстановление ограничено.

### 5.2 Пустые состояния

Нужны пустые состояния для:

- отсутствия чатов;
- отсутствия истории входов;
- отсутствия дополнительных активных устройств;
- неудачного поиска пользователя;
- отсутствия интернет-соединения.

### 5.3 Ошибки

Базовые ошибки:

- неверный AraChat ID или пароль;
- Telegram Login Widget не прошёл проверку;
- username занят;
- username содержит недопустимые символы;
- PIN введён неверно;
- PIN заблокирован;
- резервный код неверный;
- превышено количество попыток;
- WebSocket отключён;
- сообщение не отправлено.

Минимальные группы состояния:

- текущая сессия;
- язык интерфейса;
- список чатов;

- активные устройства;

### 8.3 Работа с токенами

Решение для Web Core:

- пользовательская сессия действует до 30 дней;
- refresh token действует до 30 дней и хранится безопасно через httpOnly cookie, если backend и deployment позволяют;
- access token должен быть короткоживущим, чтобы снизить риск при утечке; конкретное значение выбирается при реализации, но не должно превышать срок сессии;
- при logout refresh token отзывается;
- при завершении сессии на устройстве соответствующий refresh token отзывается.

Если выбран другой способ хранения токенов, он должен быть отдельно зафиксирован перед реализацией.

## 9. Backend-архитектура Web Core

Стек:

- Python;
- FastAPI;
- PostgreSQL;
- Redis;
- WebSocket.

### 9.1 Backend-модули Web Core

- `auth` — регистрация, вход, Telegram Login Widget, пароли, сессии;
- `users` — пользователь и профиль;
- `nexus_id` — генерация и проверка уникальности AraChat ID;
- `username` — проверка и изменение username;
- `security` — PIN, recovery code, rate limiting;
- `devices` — доверенные устройства и активные сессии;
- `chats` — личные чаты;
- `messages` — текстовые сообщения;
- `realtime` — WebSocket-события;

## 14. PIN, trusted device и recovery code

### 14.1 PIN

Правила:

- 4–8 цифр;
- 5 попыток;
- срок доверия устройства — 1 год;
- блокировка после превышения попыток;
- сброс через настройки;
- не хранить в открытом виде.

### 14.2 Trusted device

Доверенное устройство определяется через:

- device id;
- refresh token;
- локальный признак доверия;
- user agent metadata.

Выбранный механизм device id для PWA:

1. Клиент генерирует случайный `device_id` через Web Crypto API.
2. `device_id` сохраняется локально в IndexedDB или localStorage как идентификатор установки приложения/браузера.
3. Сервер хранит только связку `user_id + device_id + session metadata`.
4. При logout или удалении доверенного устройства сервер отзывает refresh token и помечает device id как недоверенный.
5. Если пользователь очистил данные браузера, device id теряется, и устройство считается новым.

Важно: fingerprinting не должен быть агрессивным и не должен нарушать приватность. Device id создаётся приложением случайно, а не собирается через скрытую идентификацию браузера, canvas fingerprinting, перечень шрифтов или другие скрытые методы.

### 14.3 Recovery code

Правила:

- 24 символа;
- группы по 4;
- показывается один раз;
- хранится только хеш;
- 5 попыток;
- после успешного использования старый код отзывается;
- пользователь получает новый код.

## 15. Telegram-бот восстановления

### 15.1 Назначение

Telegram-бот восстановления нужен для случаев, когда пользователь не может восстановиться штатно через пароль, Telegram Login Widget или резервный код.

### 15.2 Минимальный flow бота

1. `/start`.
2. Бот объясняет назначение.
3. Пользователь вводит AraChat ID.
4. Бот создаёт заявку.
5. Пользователь получает сообщение, что заявка передана на проверку.
6. Админ видит заявку в админ-панели.

### 15.3 Безопасность бота

- бот не должен принимать пароль, PIN или резервный код;
- бот не должен отправлять новый пароль;
- бот не должен автоматически восстанавливать доступ без backend-проверки;
- бот фиксирует Telegram user ID;
- все заявки логируются;
- подозрительные частые заявки ограничиваются rate limiting.

Решение для Web Core по заявкам без совпадающего Telegram identity:

- так как первичная регистрация выполняется через Telegram Login Widget, каждый аккаунт Web Core должен иметь привязанный Telegram identity;
- если Telegram user ID из заявки бота не совпадает с Telegram identity аккаунта, восстановление доступа не выполняется;
- если у аккаунта по технической ошибке отсутствует Telegram identity, автоматическое или ручное восстановление через бота запрещено до отдельного расследования владельцем проекта;
- администратор может только отклонить заявку или пометить её как требующую расследования;
- администратор не должен выдавать доступ по описанию профиля, username, аватарке или другим легко узнаваемым данным.

5. PIN заблокирован.
6. Recovery code заблокирован после 5 попыток.
7. WebSocket отключился во время отправки сообщения.

9. Пользователь вошёл на двух устройствах одновременно.

12. Пользователь не имеет привязанного Telegram identity и просит ручное восстановление.

## 23. Принятые решения Web Core перед реализацией

1. PIN можно пропустить при создании профиля.
2. Если пользователь пропустил PIN, он может добавить его позже в настройках.
3. Username имеет длину от 3 символов.
4. Username может содержать только латинские буквы и цифры `0–9`.
5. В username запрещены маты, оскорбительные слова и любой 18+ контент.
6. Пароль имеет длину от 5 до 30 символов.
7. Пароль может содержать латинские буквы в нижнем и верхнем регистре и цифры `0–9`.
8. Срок пользовательской сессии и refresh token — до 30 дней.
9. Access token должен быть короткоживущим; конкретное значение выбирается при реализации, но не превышает срок сессии.
10. AraChat ID показывается только в профиле.
11. Личный чат можно создать через поиск по username или прямой ввод AraChat ID.
12. Device id для PWA генерируется случайно через Web Crypto API и хранится локально без скрытого fingerprinting.
13. В Web Core используются только 20 встроенных аватаров: животные, люди и роботы.
14. Загрузка собственной аватарки не входит в Web Core.
15. Для восстановления через Telegram-бот требуется совпадение Telegram identity из заявки с Telegram identity аккаунта.
16. Если Telegram identity не совпадает, восстановление доступа в Web Core не выполняется.
17. Основная тема по умолчанию — AraChat Halo.
18. В настройках пользователь может переключить тему на AraChat Orbit или AraChat Aurora.
19. Выбранная тема сохраняется в профиле пользователя и применяется без перезагрузки страницы.

## 24. Дизайн-направления Web Core

В Web Core поддерживаются три дизайн-направления:

1. **AraChat Halo** — тема по умолчанию.
2. **AraChat Orbit** — альтернативная тема с орбитальным мотивом связей.
3. **AraChat Aurora** — альтернативная мягкая светящаяся тема.

Пользователь может выбрать тему в настройках внешнего вида. Выбор темы сохраняется в профиле пользователя в поле `design_theme` и синхронизируется между устройствами.

### 24.1 Общие правила тем

- все темы используют одну структуру экранов и компонентов;
- темы различаются цветами, фоном, акцентами, тенями, декоративными мотивами и состояниями выделения;
- переключение темы не должно менять UX-логику;
- темы должны поддерживать responsive layout;
- темы должны быть реализованы через дизайн-токены, а не через дублирование компонентов;
- выбранная тема применяется без перезагрузки страницы;
- тема должна работать на стартовом экране, auth-экранах, списке чатов, личном чате, профиле и настройках.

**AraChat Aurora** — альтернативная мягкая тема с эффектом цифрового сияния.

Характер: дружелюбный, воздушный, светящийся, спокойный и семейный.

Фирменный мотив: мягкие градиентные пятна, aurora-подсветка активных элементов и плавные переходы состояний.

Палитра:

- light background: `#F7F8FF`;
- light surface: `#FFFFFF`;
- dark background: `#0E1020`;
- dark surface: `#171B33`;
- primary: `#7C5CFF`;
- secondary: `#58D7FF`;
- accent: `#FF8FC7`;
- text primary: `#14142B`;
- text secondary: `#697086`.

### 24.5 Типографика и форма

Основной шрифт Web Core: **Manrope**.

Правила формы:

- базовое скругление карточек: 20–28 px;
- скругление кнопок: 999 px или крупная капсула;
- сообщения: мягкие bubble/capsule формы;
- аватарки: круглые;
- активные элементы: выделение через theme-specific glow/ring;
- плотность интерфейса: средняя, без перегруза.

### 24.6 Настройки темы

В настройках внешнего вида пользователь видит три карточки:

1. AraChat Halo — “по умолчанию”.
2. AraChat Orbit — “орбитальная тема”.
3. AraChat Aurora — “мягкое сияние”.

Каждая карточка показывает мини-preview:

- фон;
- пример chat bubble;
- пример аватарки;
- primary button;
- активное состояние.

После выбора темы:

- тема применяется сразу;
- выбор сохраняется в профиле пользователя;
- тема синхронизируется между устройствами;
- если тема не загружена или повреждена, приложение возвращается к AraChat Halo.

# AraChat Desktop: фактический статус и план завершения

**Обновлено:** 17 октября 2026 года

## 1. Честный статус

Desktop-клиент в `apps/pc` больше не является только макетом первого запуска.
В репозитории реализован самостоятельный Tauri 2 + React клиент с основными
сценариями мессенджера. На 17 октября он **готов к системному тестированию и
сборке release candidate**, но ещё **не готов к публичному выпуску**.

Нельзя описывать текущую работу как «доделать экраны входа»: основной объём
функциональности уже написан. Главная задача теперь — проверить её с настоящим
API на двух платформах, устранить подтверждённые дефекты и подготовить
распространяемые пакеты.

### Подтверждённые результаты проверки

| Проверка | Результат |
| --- | --- |
| Production-сборка React/Vite (`npm run build:desktop`) | Успешно: обработано 62 модуля. |
| Модульные тесты записи медиа (`node --test apps/pc/src/features/chats/useMediaRecorder.test.js`) | Успешно: 3 из 3 тестов пройдены. |
| Tauri release для macOS Apple Silicon (`tauri build --bundles dmg`) | Успешно: собраны release-бинарник и `AraChat_0.1.0_aarch64.dmg`. |
| Целостность локального DMG | Успешно проверена командой `hdiutil verify`. |
| Windows-пакет, установка и ручное тестирование | Не проверены в текущем окружении. |
| Подпись Windows, подпись и notarization macOS | Не настроены. |

Ручной workflow [`.github/workflows/desktop-build.yml`](../.github/workflows/desktop-build.yml)
собирает `.dmg` на `macos-14` и NSIS `.exe` на `windows-latest`, но наличие
workflow не является доказательством прохождения реальной Windows-проверки.

## 2. Что уже реализовано в коде

### 2.1. Нативная основа и выпуск

- отдельное приложение `apps/pc` на Tauri 2, Vite и React;
- начальное окно `1200 x 800`, минимальный размер `960 x 680`, кастомная
  верхняя панель и действия свернуть/развернуть/закрыть;
- Tauri permissions ограничены операциями окна, уведомлениями и открытием
  двух доверенных правовых URL;
- production API задаётся публичной переменной `VITE_API_BASE_URL`; в текущей
  production-конфигурации это `https://aramsg.ru`;
- GitHub Actions для macOS Apple Silicon DMG и Windows x64 NSIS;
- разрешения macOS для камеры и микрофона заданы в `Info.plist`.

### 2.2. Первый запуск, языки и темы

- интерактивный приветственный экран с анимированным 2D-брендовым знаком,
  пропуском, переходами ко входу и регистрации, правовыми ссылками;
- русская и английская локали;
- светлая и тёмная темы;
- локально сохраняются безопасные настройки интерфейса: язык, тема, плотность,
  звук уведомлений, состояние уведомлений и факт просмотра приветствия;
- используется 2D-сцена бренда; 3D-модель ара не требуется для текущего
  desktop-релиза.

### 2.3. Авторизация и сессия

- вход по e-mail и паролю через настоящий API;
- трёхшаговая регистрация: страна, подтверждение e-mail кодом, имя, username,
  пароль и принятие правовых документов;
- получение и обновление access/refresh-токенов, выход из аккаунта;
- persistent refresh-токен хранится через системное защищённое хранилище:
  macOS Keychain или Windows Credential Manager, а не в `localStorage`;
- при невозможности сохранить refresh-токен сессия остаётся только в памяти
  текущего запуска, без молчаливой небезопасной замены хранилища.

### 2.4. Рабочее пространство и личные чаты

- список личных чатов, поиск, открытие, скрытие списка и создание direct-чата
  после поиска пользователя по публичным данным;
- загрузка истории и отправка текстовых сообщений;
- отправка фото, видео, документов и файлов; голосовые сообщения и
  видеозаметки через `MediaRecorder` с ограничениями по времени и размеру;
- ответы, редактирование своих текстовых сообщений, удаление, закрепление,
  реакции и отметка прочтения;
- typing, presence, статусы доставки и обновление чатов через WebSocket;
- heartbeat, повторное подключение и повторная синхронизация после reconnect;
- отдельный клиентский контур E2EE для личных чатов: генерация ключей Web Crypto,
  регистрация публичных ключей на API, шифрование текста и вложений,
  расшифрование и индикация статуса ключа.

Приватные ключи E2EE являются неэкспортируемыми `CryptoKey` и хранятся в
IndexedDB webview. Это реализованный механизм, но не основание заявлять
криптографическую готовность без отдельного аудита и межплатформенной проверки.

### 2.5. Профиль, настройки, уведомления и звонки

- профиль: загрузка и изменение отображаемого имени и username, показ AraChat
  ID;
- настройки внешнего вида, языка и плотности интерфейса;
- настройки native-уведомлений, PIN, смены пароля и e-mail через коды;
- список активных устройств, отзыв устройства, история входов и выход;
- центр уведомлений и нативные уведомления Tauri для событий, полученных по
  realtime в запущенном приложении;
- клиентский WebRTC-контур личных аудио- и видеозвонков: входящий/исходящий
  вызов, микрофон, камера, отключение звука, завершение, сигналинг;
- демонстрация экрана/окна во время звонка, пауза, остановка и управление
  доступным звуком демонстрации.

## 3. Что пока не следует считать завершённым

### P0 — обязательно до закрытой беты

1. **Сквозная проверка с настоящим API.**
   Проверить регистрацию, вход, восстановление сессии, два пользователя,
   сообщения, медиа, WebSocket/reconnect, уведомления и logout на staging или
   production-стенде. Для e-mail сценариев должны быть готовы SMTP и тестовые
   почтовые ящики.

2. **Проверка на целевых ОС.**
   Выполнить ручную матрицу на macOS 14+ (Apple Silicon) и Windows 10+ x64:
   установка, чистый запуск, окно, темы, RU/EN, клавиатура, камера, микрофон,
   запись медиа, звонки и демонстрация экрана. Отдельно собрать и установить
   Windows NSIS `.exe`.

3. **Регрессия и автоматизация тестов.**
   Сейчас есть только 3 модульных теста для выбора MIME-типа записи. Добавить
   тесты API-адаптеров и ключевых UI-состояний, а затем сквозной smoke-набор для
   auth, чата и WebSocket. Каждый исправленный дефект должен получить защитный
   тест, если это практически возможно.

4. **Безопасность и релизная конфигурация.**
   Проверить CORS для `tauri://localhost` и `http://tauri.localhost`, отсутствие
   секретов в package/DMG/логах и сценарии истёкшей сессии. Настроить строгую
   Content Security Policy: в `tauri.conf.json` сейчас указано `"csp": null`.
   Провести отдельную ревизию E2EE: жизненный цикл ключей, смена ключа,
   межустройственная доставка и совместимость с web-клиентом.

5. **Подготовка к распространению.**
   Настроить Apple Developer ID, подпись и notarization macOS, а также
   сертификат подписи Windows. До этого возможна только контролируемая бета с
   понятными предупреждениями Gatekeeper/SmartScreen, а не полноценный
   публичный выпуск.

### P1 — функциональные пробелы после стабилизации P0

- вход по AraChat ID и PIN; восстановление пароля в desktop-интерфейсе;
- подключение VK ID и Яндекс ID после готовности backend OAuth;
- загрузка/выбор аватара, телефон и настройки приватности профиля;
- пользовательская поддержка, жалобы и блокировка пользователей;
- решение по поведению welcome: значение `hasSeenWelcome` сохраняется, но ещё
  не используется для автоматического выбора маршрута при следующем запуске;
- фоновая доставка уведомлений, автозапуск и автообновления — только после
  отдельного продуктового и платформенного решения;
- расширение функциональности чатов только после результатов закрытой беты.

### Вне текущей обещанной границы

- групповые чаты и каналы;
- групповые звонки и SFU;
- обещание полноценной криптографической защищённости E2EE до независимой
  проверки;
- публичное распространение неподписанных приложений как готового релиза.

## 4. Последовательность завершения

1. Сформировать из раздела P0 задачи с владельцем, критерием приёмки и тестовой
   средой.
2. Передать QA актуальные macOS-пакет и Windows-пакет из CI.
3. Пройти сквозные сценарии на двух реальных учётных записях и обеих ОС.
4. Исправлять сначала P0-дефекты, не добавляя новые функции.
5. После code freeze выполнить полный регресс, проверить артефакты и выпустить
   release candidate для закрытой беты.
6. Решение о расширении функциональности принимать только по обратной связи
   беты и измеренным дефектам.

## 5. Критерий готовности release candidate

Release candidate готов к закрытой бете, когда одновременно:

1. production frontend, macOS `.dmg` и Windows NSIS `.exe` собираются из
   зафиксированной версии кода;
2. установка и основные сценарии подтверждены на macOS 14+ и Windows 10+;
3. registration/login/session, личный чат, медиа, realtime/reconnect и
   уведомления прошли сквозной smoke на реальном API;
4. аудио-/видеозвонок и демонстрация экрана проверены на физических устройствах
   или честно исключены из беты с выключенным интерфейсом;
5. нет открытых критических и высокоприоритетных дефектов;
6. проверены RU/EN, светлая/тёмная темы, клавиатурная навигация, reduced motion
   и окна минимального размера;
7. пройдены проверка токенов/секретов, CORS и согласованная security review;
8. подготовлены список известных ограничений, инструкция бета-тестера и канал
   обратной связи.

Подпись Windows и notarization macOS остаются обязательными условиями
**публичного** распространения, даже если закрытая бета пройдёт успешно.

# План первого frontend-этапа AraChat Desktop

## Цель и границы

Создать новый UI-клиент в `apps/pc` на Tauri + React для macOS и Windows. В эту итерацию входят только экраны первого запуска, входа и регистрации. Интерфейс должен быть кликабельным и выглядеть как приложение, но не должен выдавать локальные заглушки за работающую авторизацию или OAuth.

Чаты, профиль, настройки, вложения и звонки останутся следующими UI-итерациями; их требования уже отражены в журнале продуктовых решений.

## Решения реализации

1. **Каркас desktop-приложения**
   - Создать Tauri 2 + Vite + React приложение в `apps/pc`, не изменяя работающий web-клиент.
   - Настроить стартовое окно `1200×800`, кастомный title bar и отдельные правила для macOS и Windows.
   - Добавить безопасное управление окном: зона перетаскивания без интерактивных вложенных элементов, доступные действия окна для Windows.

2. **Основа дизайн-системы**
   - Ввести семантические CSS-токены для фонов, поверхностей, текста, границ, фокуса, состояний и фирменных акцентов.
   - Реализовать светлую и тёмную темы, следуя системному предпочтению при первом запуске и сохраняя ручной выбор пользователя.
   - Использовать адаптивный desktop-макет с минимально поддерживаемым размером `1200×800` и отсутствием критичного горизонтального скролла.

3. **Локализация и настройки первого запуска**
   - Добавить словари `ru` и `en` для всех строк трёх экранов.
   - Автоматически выбирать русский язык при русской системной локали, английский — в остальных случаях; ручной выбор сохранять локально.
   - Хранить локально только безопасные UI-настройки: тема, язык, выключенный звук и факт просмотра вступления. Учётные данные и токены до backend-этапа не сохранять.

4. **Приветственный экран**
   - Реализовать последовательность сцены, доступные кнопки пропуска, включения звука, языка и перехода к авторизации.
   - Добавить частицы-перья, дерево с веткой, появление логотипа и управляемую сцену с поддержкой reduced motion.
   - Создать изолированный `ParrotScene` с контрактом для модели `.glb`/`.gltf`; до её поставки использовать честно обозначенный статичный брендовый кадр как резервное состояние.
   - Подключить настоящую 3D-модель только после передачи ассета; полёт, посадка, взмах и слежение головы будут анимациями модели, а не имитацией на 2D-изображении.

5. **Вход**
   - Спроектировать e-mail и пароль, опцию доверенного устройства, переключатель языка/темы, а также доступные состояния фокуса, ошибки и загрузки.
   - Предусмотреть условный экран e-mail-кода для нового устройства, который backend сможет открыть по своему ответу.
   - Показать VK ID и Яндекс ID как интеграционные точки с корректным состоянием «скоро будет» до реализации OAuth, без обманчивой авторизации.

6. **Регистрация**
   - Реализовать три последовательных шага с индикатором прогресса и проверками на стороне интерфейса.
   - Поддержать ввод e-mail-кода, имя, username, локальную предварительную загрузку аватара, надёжный пароль, подтверждение документов.
   - Подготовить контракты событий и состояние, чтобы в следующем этапе заменить локальный демонстрационный режим реальными API-вызовами без переделки макета.

7. **Проверка качества**
   - Проверить production-сборку frontend и Tauri-пакета, если в окружении доступны Node.js, Rust и системные зависимости Tauri.
   - Проверить сценарии: первый запуск, пропуск, reduced motion, обе темы, обе локали, клавиатурная навигация, ошибки и переходы входа/регистрации.
   - Отдельно проверить читаемость текста и видимость фокуса в обеих темах.

## Риски и меры

| Риск | Мера |
| --- | --- |
| Для настоящей 3D-анимации нет модели с ригом | Сначала поставить компонентную интеграцию и честный статичный резерв; подключить движение после получения `.glb`/`.gltf`. |
| Тяжёлая 3D-сцена замедлит первый запуск | Ограничить полигоны и текстуры, загружать сцену по требованию, предоставить статичный режим при reduced motion. |
| Будущий backend изменит формы | Не имитировать серверные успехи; изолировать форму и адаптер API от визуальных компонентов. |
| Различия macOS и Windows в окне | Использовать API Tauri и платформенные стили вместо одного поведения для всех систем. |

## Критерий готовности этапа

Пользователь может открыть desktop-клиент, увидеть или пропустить вступление, изменить язык/тему/звук, перейти на экран входа и пройти все три визуально завершённые шага регистрации. Все состояния доступны с клавиатуры, отображаются на русском и английском, а 3D-сцена либо воспроизводит переданный 3D-ассет, либо явно работает как статичный резерв до его поставки.

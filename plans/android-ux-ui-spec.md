# Android UX/UI: утверждённая спецификация AraChat v1

## 1. Статус и границы

Этот документ фиксирует утверждённые продуктовые и UX-решения для нативного
Android-клиента AraChat. Он является источником реализации интерфейса вместе с
`plans/android-rustore-plan.md` и актуальными API-контрактами.

На дату утверждения приложение `apps/android` не создаётся. Документ не
означает готовность Android push-доставки или звонков. Встроенная поддержка
утверждена как отдельный серверный контур, но до его реализации форма обращений
в клиенте не показывается.

В Android v1 не входят публичные ветки и комментарии. Звонки в интерфейсе
показываются только как недоступное действие с точной строкой:

```text
Звонки скоро появятся
```

## 2. Базовые принципы

### 2.1. Визуальное направление

**Prism Glass + AraChat Halo** — оригинальная визуальная система AraChat,
вдохновлённая ощущением глубины и полупрозрачности Liquid Glass, но не копия
интерфейсов Apple.

- Стекло применяется к навигации, заголовкам, нижним листам, меню и composer.
- Длинный контент, сообщения, тексты ошибок и safety-состояния остаются
  преимущественно непрозрачными и контрастными.
- Halo — узнаваемый световой контур вокруг знака/аватара, а не декоративный
  эффект, закрывающий контент.
- В высокой контрастности и при отключённой анимации прозрачность, blur и
  движение сокращаются до статичных доступных состояний.

### 2.2. Адаптивность и доступность

- Все строки существуют в самостоятельных RU/EN-каталогах.
- Язык первого запуска выбирается по языку ОС: RU или EN, иначе RU; изменить
  его можно сразу и позже в настройках.
- Минимальная зона касания — 48 dp.
- Поддерживаются TalkBack, увеличенный шрифт, поворот, клавиатура, split-screen
  и оконный режим.
- На телефоне и в узком окне список и чат открываются отдельными экранами.
- На широком планшете используется две панели: список слева, выбранный чат или
  пустое состояние справа.
- Смысл статуса, ошибки и действия не передаётся только цветом или иконкой.
- Приложение не показывает необработанный `detail` сервера: известные ошибки
  сопоставляются с локализованными сообщениями.

## 3. Главная навигация

На телефоне — плавающая нижняя Prism Glass-капсула с четырьмя вкладками:

```text
Чаты / Поиск / Профиль / Настройки
```

- В открытом чате нижняя навигация скрыта.
- На широком планшете капсула становится компактной вертикальной навигацией
  слева.
- Переходы сохраняют знакомую Telegram-логику, но не повторяют его цвета,
  иконки, тексты или компоновку буквально.

## 4. Первый запуск, регистрация и доступ

### 4.1. Выбранный сценарий

Утверждён вариант A: **«Спокойный пошаговый путь»**. Один основной шаг занимает
один экран, показывается индикатор `1 из 4`–`4 из 4`.

Регистрация e-mail-first и соответствует текущему API:

1. e-mail → `POST /auth/email-verification/start`;
2. шестизначный код → `POST /auth/email-verification/confirm`;
3. username и встроенный аватар;
4. пароль, необязательный PIN, принятие документов →
   `POST /auth/register/complete`.

OAuth VK/Yandex **не показывается** как путь регистрации или создания нового
аккаунта: сервер поддерживает его только для существующих вручную привязанных
учётных записей.

### 4.2. Welcome

```text
[ Halo / знак AraChat ]

AraChat
Личные сообщения — без лишнего.

[ Создать аккаунт ]
Войти

Русский ▾
```

Ссылки на правовые документы доступны внизу экрана, но не отвлекают от главных
действий.

### 4.3. Регистрация

#### Шаг 1. Подтверждение e-mail

```text
Подтвердите e-mail                         1 из 4
На него придёт код для создания аккаунта.

[ E-mail                                 ]
[ Получить код                           ]

[ _  _  _  _  _  _ ]
Код отправлен на name@example.com
Отправить повторно через 00:42
```

- Ввод кода использует шесть визуальных ячеек, поддерживает обычный цифровой
  ввод и вставку.
- При изменении e-mail код и подтверждённый verification ID сбрасываются.
- Состояния лимита и ошибки отображаются понятным локальным текстом.

#### Шаг 2. Username и встроенный аватар

```text
Как вас будут находить?                    2 из 4

[ @username                              ]
От 3 символов. Используйте латинские буквы и цифры.

Выберите аватар
[ встроенные варианты ]

[ Продолжить                            ]
```

- Доступность username проверяется после короткой паузы и при уходе из поля.
- Встроенный аватар выбирается без запроса доступа к галерее.
- Display name не обязателен на старте, потому не принуждается в регистрации.

#### Шаг 3. Пароль и PIN

```text
Придумайте пароль                          3 из 4

[ Пароль                            👁   ]
От 5 до 30 символов.

Быстрый вход на этом устройстве
Необязательно

[ Создать PIN-код ]
Не сейчас
```

- Создание PIN открывает компактный локальный шаг: ввод и повтор PIN.
- PIN состоит из 4–8 цифр.
- PIN — только быстрый вход на доверенном устройстве; он не заменяет пароль и
  не служит способом восстановления доступа.

#### Шаг 4. Документы и создание

```text
Перед созданием аккаунта                   4 из 4

☐ Я принимаю Политику конфиденциальности
☐ Я принимаю Условия использования

[ Создать аккаунт ]
```

Обе отметки обязательны. После успешной регистрации пользователь сразу попадает
в «Чаты» и видит полезное пустое состояние с действием «Найти пользователя».

### 4.4. Обычный вход

```text
Войдите в AraChat

[ E-mail или AraChat ID                  ]
[ Пароль                            👁   ]

Забыли пароль?

[ Войти ]

Нет аккаунта? Создать аккаунт
```

Для входа используются текущие поддерживаемые идентификаторы: e-mail или
16-значный AraChat ID. Телефон и username не предлагаются как варианты входа.

### 4.5. Быстрый вход по PIN

Он появляется только для ранее известного аккаунта, который создал PIN на
текущем `device_id`:

```text
[ Аватар ]
Алексей
a•••••@example.com

Введите PIN
[ _  _  _  _  _  _ ]

Войти с паролем
```

Хотя API PIN-входа также получает идентификатор, UI сохраняет его только как
контекст уже известного локального аккаунта. Пользователь не вводит его заново.
При истечении доверия, отзыве PIN или блокировке попыток интерфейс ведёт к
обычному входу с паролем и не раскрывает внутренние технические причины.

### 4.6. Восстановление пароля

```text
Укажите e-mail
Мы отправим код для создания нового пароля.

[ E-mail                                 ]
[ Получить код                           ]
```

После начала восстановления всегда показывается нейтральный текст:

```text
Если этот адрес связан с AraChat, мы отправили код.
```

Далее пользователь вводит код и новый пароль на отдельном экране. После успеха
ему предлагается обычный вход. Наличие аккаунта по введённому e-mail не
раскрывается.

### 4.7. Анимация входа: AraChat Halo

Утверждённая motion-концепция — **AraChat Halo**. Она короткая,
неблокирующая и служит переходом к действию, а не заставкой.

#### Первый запуск

1. На фоне темы появляется стеклянный круг со знаком AraChat.
2. Вокруг него проходят две полупрозрачные Halo-дуги.
3. Дуги собираются в тонкое световое кольцо и остаются статичным Halo.
4. Название и основные действия мягко появляются снизу.

#### Переход между шагами авторизации

- Нажатая главная кнопка слегка сжимается к центру.
- Halo делает один краткий световой импульс.
- Текущий шаг растворяется, следующий поднимается снизу на 12–16 dp.
- Прогресс регистрации непрерывно заполняет следующий сегмент.

#### Успешный вход

- Кнопка `Войти` превращается в компактную капсулу со статусом `Входим…`.
- Halo однократно расширяется и растворяется.
- На его месте последовательно проявляются `Чаты`, «Сохранённые сообщения» и
  не более трёх видимых строк списка.

#### Ограничения motion

- Нет бесконечной анимации на welcome-экране.
- Анимация не блокирует элементы управления.
- При ожидании сети показывается честный статус, а не повторяющийся
  декоративный эффект.
- Ошибка подсвечивает конкретное поле и даёт мягкий тактильный отклик; тряска
  всего экрана не используется.
- При отключённой системной анимации или высокой контрастности остаётся почти
  мгновенное статичное появление без blur, масштабирования и движущихся бликов.
- TalkBack получает статусы «Выполняется вход», затем «Вход выполнен» либо
  локализованное описание ошибки.

## 5. Чаты

### 5.1. Вкладка «Чаты»: Focused Inbox

- Заголовок `Чаты` и постоянный поиск только по существующим диалогам.
- Закреплённые «Сохранённые сообщения».
- Личный чат: аватар, online state, имя, время, preview, unread badge,
  краткая активность набора или загрузки.
- FAB `+` открывает вкладку «Поиск» и ставит фокус в поиск пользователя.
- Swipe-left скрывает диалог; snackbar: `Диалог скрыт` и действие `Вернуть`.
- Pull-to-refresh и ненавязчивое offline/reconnect состояние.
- Пустое состояние предлагает `Найти пользователя`.
- В preview списка не обещаются галочки доставки: текущий API preview не
  содержит `delivery_status`.

### 5.2. Личный чат: AraChat Balance

- Привычная логика Telegram/WhatsApp/MAX, но оригинальная визуальная система.
- Glass header, composer и меню; пузырьки сообщений преимущественно
  непрозрачные для читаемости.
- Header: назад, аватар/имя/статус, звонок, overflow.
- Звонок показывает только `Звонки скоро появятся`.
- Строка закреплённого сообщения появляется лишь при существующем закреплении.
- Поддерживаются reply, реакции, редактирование/удаление своих сообщений и
  long-press действия.
- Overflow: профиль, обои чата, скрыть чат, заблокировать, пожаловаться.
- Блокированный диалог становится недоступным. Клиент соблюдает серверное
  состояние и не раскрывает его причину.
- Поддерживаемые сервером обои: `default`, `grid`, `waves`, `aurora`, `paper`,
  `night`.
- Кнопка вложений может быть показана в дизайне, но реальные медиа включаются
  только после отдельной проверки native recording/playback, разрешений и
  фоновых сценариев.

## 6. Поиск

Утверждён единый поиск:

- поле фокусируется автоматически и принимает `@username`, username или точный
  AraChat ID;
- запрос начинается от двух символов с debounce;
- результат: аватар, display name, `@username`, признак официального аккаунта;
- касание открывает сначала bottom sheet публичного профиля, где главное
  действие — `Написать сообщение`;
- поиск по телефону остаётся вторичным bottom sheet: страна и номер;
- нейтральное пустое состояние и состояние блокировки:

```text
Пользователь не найден
Проверьте username или AraChat ID.
```

Публичный профиль другого человека не показывает полный или замаскированный
AraChat ID: текущий API этого не выдаёт. Нельзя раскрывать существование
заблокированного пользователя.

## 7. Профиль

Утверждён гибрид «Карточка + быстрое редактирование»:

- identity card с аватаром/Halo, display name и `@username`;
- AraChat ID в Prism-блоке, разбитый на группы `1234 5678 9012 3456`, с
  копированием и подтверждением;
- имя, username и телефон — компактные строки, открывающие сфокусированный
  sheet или экран редактирования, а не постоянно открытую большую форму;
- аватар открывает picker и preview;
- телефон по умолчанию скрыт от других и управляется отдельным поясняющим
  переключателем видимости;
- e-mail, пароль, устройства и PIN находятся в настройках, а не в профиле;
- безопасная подсказка username: `От 3 символов. Используйте латинские буквы и
  цифры.` Без обещаний поддержки подчёркиваний.

## 8. Настройки

Структура: плотный быстрый список, знакомый пользователям Telegram по логике
группировки, но с оригинальными AraChat-компонентами.

```text
Настройки                                      ✎

[ Аватар / Имя / @username / AraChat ID · •••• 4821 ] >

АККАУНТ
E-mail и пароль >
Устройства >
История входов >
PIN-код >

НАСТРОЙКИ
Уведомления >
Язык                                        Русский >
Оформление                                  Prism Glass >

ПРИВАТНОСТЬ И БЕЗОПАСНОСТЬ
Заблокированные пользователи >
Мои жалобы >

ПОМОЩЬ
Поддержка AraChat >
Правила сообщества >
Политика и документы >

Выйти из аккаунта
Удалить аккаунт
```

- Карточка профиля и ✎ ведут в профиль или быстрое редактирование.
- Уведомления честно сообщают, что Android delivery пока не подключён, до
  выбора и тестирования реального provider. Фиктивный переключатель запрещён.
- «Поддержка AraChat» открывает отдельный раздел реальных обращений только
  после готовности backend-контракта. До этого действие не показывает
  фиктивную локальную форму или несуществующий адрес.
- Удаление аккаунта требует явного подтверждения.

### 8.1. Поддержка AraChat

Поддержка — самостоятельный раздел, а не личный чат с владельцем и не
почтовая ссылка. Он доступен только в авторизованной сессии.

- Экран содержит список собственных обращений: категория, фрагмент первого
  сообщения, последний ответ, дата и статус `Открыто`, `В работе`, `Ждём ваш
  ответ` или `Решено`.
- Кнопка `Новое обращение` открывает компактную форму: категория и текст. Над
  полем всегда показано предупреждение: `Не отправляйте пароль, PIN-код или
  код из письма.`
- Экран обращения показывает текстовую переписку, видимый статус и поле ответа;
  пользователь может ответить, пока обращение не решено, либо создать новое
  обращение при необходимости.
- В первой версии нельзя прикреплять скриншоты, файлы или другие вложения.
- Ответ поддержки создаёт внутреннее уведомление. Android push не обещается,
  пока Universal Push с маршрутами RuStore, FCM и HMS не пройдёт отдельный
  signed-device прототип.
- Технические ошибки, ограничения частоты и отсутствие сети объясняются
  локализованно и не теряют введённый текст.

## 9. Границы честности клиента

- Android tokens не являются Web Push/VAPID subscriptions.
- Токены Android можно хранить по серверному контракту, но Android delivery не
  считается реализованной, пока не выбран и не протестирован provider.
- Блокировка должна оставаться серверной: поиск, личные чаты, сообщения,
  realtime, звонки и push. UI лишь корректно отражает ответ сервера.
- В v1 не обещаются возможности, для которых серверный или native-контур ещё
  не готов: звонки, реальные вложения в поддержке, Android push и поддержка
  через форму до запуска её серверного контура.

## 10. Готовность к реализации

Визуальное направление, навигация, ключевые экраны, auth и motion утверждены.
Перед созданием `apps/android` остаются технические решения из Android-плана:

1. подтвердить minimum SDK и совместимые версии React Native / Android Gradle;
2. выбрать и проверить push для RuStore и direct APK на подписанном test app;
3. реализовать и проверить API и веб-админку встроенных текстовых обращений;
4. подтвердить применённость Alembic migration `0024_mobile_push_safety` к
   intended dev/staging базе;
5. подтвердить production-зависимости: HTTPS/WSS, SMTP, storage, backups,
   авторизацию private media и multi-process realtime strategy.

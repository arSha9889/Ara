# AraChat Web — Signal Core Design System

## 1. Статус решения

**Статус:** утверждено для реализации Web.

Signal Core становится единой дизайн-системой AraChat Web. Её эталонная
визуальная реализация — текущая тёмная палитра **AraChat Comet**, развиваемая
из «космической витрины» в спокойную среду ежедневного общения.

Это решение заменяет для Web прежний подход, где Halo, Comet и Liquid Glass
считались тремя равными самостоятельными визуальными направлениями. Теперь
это три палитры одной системы:

- **Signal Core / Comet** — основная палитра и значение по умолчанию для новых
  установок;
- **Halo** — светлая, мягкая альтернативная палитра;
- **Liquid Glass** — светлая стеклянная альтернативная палитра с ограниченной
  прозрачностью.

Выбранные пользователями Halo и Liquid Glass не сбрасываются. Изменяется
только значение для отсутствующей или некорректной настройки темы: `comet`.

## 2. Цель

Создать узнаваемый, быстрый и доступный интерфейс мессенджера, в котором
образ сигнала-кометы выражает связь между людьми, но не мешает читать
переписку, управлять безопасностью или работать на маленьком экране.

Signal Core применяется к публичному сайту, onboarding, авторизации, чату,
профилю, настройкам, безопасности, поддержке и публичным веткам. Маршруты,
API-контракты, модель данных и уже сохранённые пользовательские предпочтения
не меняются.

## 3. Принципы

1. **Сигнал, а не декорация.** Цвет, линия и движение сообщают о состоянии:
   выбранном диалоге, непрочитанном, подключении, отправке и успехе.
2. **Чат важнее оболочки.** В переписке нет прозрачных пузырьков и шумных
   градиентов. Сообщение всегда читаемо поверх любой пользовательской обои.
3. **Плотность без тесноты.** Цельные поверхности и разделители заменяют
   множество плавающих карточек. Отступы строятся на сетке 4/8 px.
4. **Доверие видно в интерфейсе.** Безопасные, предупреждающие и опасные
   действия отличаются текстом, иконкой, цветом и подтверждением, а не только
   цветом.
5. **Одна логика на все палитры.** Палитра меняет значения токенов, но не
   структуру, размеры touch-целей, иерархию и сценарии.
6. **Движение только по событию.** Нет бесконечной декоративной анимации в
   рабочем интерфейсе; `prefers-reduced-motion` отключает движение.

## 4. Токены

### 4.1 Семантические слои

Все новые и мигрируемые стили используют семантические токены. Старые
`--background`, `--surface`, `--surface-elevated`, `--text`, `--muted`,
`--primary` и другие сохраняются как слой совместимости, пока не завершена
постепенная миграция существующих правил.

| Группа | Токены | Назначение |
| --- | --- | --- |
| Canvas | `--canvas`, `--canvas-strong`, `--canvas-glow` | Фон приложения и атмосферный свет |
| Surface | `--surface-base`, `--surface-raised`, `--surface-overlay`, `--surface-inset` | Рабочие области, панели, меню, поля |
| Content | `--content-primary`, `--content-secondary`, `--content-tertiary`, `--content-on-accent` | Текст и иконки |
| Signal | `--signal-primary`, `--signal-strong`, `--signal-trace`, `--signal-focus` | Навигация, выбранное, действие, фокус |
| Status | `--status-success`, `--status-warning`, `--status-danger`, `--status-online` | Статусы и рискованные действия |
| Chat | `--chat-incoming`, `--chat-outgoing`, `--chat-composer`, `--chat-wallpaper-scrim` | Переписка и защита от обоев |
| Geometry | `--radius-control`, `--radius-surface`, `--radius-dialog`, `--space-*` | Единый ритм компонентов |

### 4.2 Эталонная палитра Comet

| Роль | Значение |
| --- | --- |
| Canvas | `#0B0D16` |
| Canvas strong | `#101426` |
| Surface base | `#151A2C` |
| Surface raised | `#1D2440` |
| Основной текст | `#F5F7FF` |
| Вторичный текст | `#AAB4D4` |
| Signal primary / индиго | `#7888FF` |
| Signal strong / лайм | `#BFFF62` |
| Accent / фиолетовый | `#D68BFF` |
| Success / online | `#74E3A6` |
| Warning | `#FFD166` |
| Danger | `#FF7B91` |

Лайм не используется для больших текстовых массивов, исходящих сообщений или
фона экрана. Его роль — короткий и понятный сигнал: primary CTA, active trace,
unread, online и положительное завершение действия.

### 4.3 Геометрия и типографика

- Базовая сетка: 4 px; стандартные отступы: 8, 12, 16, 20, 24, 32, 40 px.
- Контролы: радиус 14 px; обычные поверхности: 20 px; диалоги: 24 px.
- Основной шрифт сохраняется: Manrope, системные fallback-шрифты.
- Заголовки остаются плотными, но крупный display-стиль применяется только на
  лендинге и onboarding; в рабочем приложении — спокойная иерархия.
- Минимальная touch-цель на touch-устройствах: 44 x 44 px.

## 5. Улучшения Signal Core

### 5.1 Signal Rail

Тонкая сигнальная линия — основной фирменный индикатор состояния:

- активный диалог: индиго-линия слева у строки, с коротким появлением точки;
- непрочитанный диалог: лаймовый импульс и числовой badge;
- активная вкладка/раздел: линия или внутренний акцент без тяжёлого градиента;
- состояние соединения: компактная цветная точка рядом с доступным текстом.

Линия не должна постоянно анимироваться. Эффект запускается при смене
состояния и отменяется при `prefers-reduced-motion`.

### 5.2 Focus Canvas

На desktop и tablet чат получает режим концентрации:

- пользователь может свернуть список диалогов до компактной полосы;
- рабочая область сообщения расширяется, навигация остаётся доступной;
- настройка локальна для браузера и не влияет на mobile;
- на mobile список и чат остаются разными экранами, отдельный режим не нужен.

### 5.3 Identity Beacon

Аватар несёт ограниченный набор понятных признаков:

- тонкое кольцо присутствия для online;
- отдельный знак для официального профиля;
- краткая вспышка кольца для нового события, но не постоянная анимация;
- системный fallback-акцент рассчитывается только из небольшой безопасной
  палитры и не заменяет текстовые обозначения статуса.

### 5.4 Quiet Depth

- Список чатов и настройки — цельные рабочие поверхности, не набор отдельных
  «парящих» карточек.
- Сильная тень доступна только overlay, меню, диалогам и composer.
- Разделение задаётся тонкой границей и тоном поверхности.
- Прозрачность остаётся только допустимой особенностью Liquid Glass и не
  применяется к основному содержимому переписки.

### 5.5 Message Rhythm

- Последовательные сообщения визуально собираются в группы через уменьшенный
  вертикальный интервал и соответствующие радиусы пузырьков.
- Время и доставка показываются в конце смысловой группы, если API/разметка
  позволяют это определить; существующие данные не выдумываются.
- Даты и системные события имеют нейтральный разделитель.
- Реакции и действия сообщения выглядят как компактные сигнальные метки.
- Входящие и исходящие пузырьки непрозрачны во всех темах.

### 5.6 Контекстные обои

Существующие `default`, `grid`, `waves`, `aurora`, `paper` и `night`
сохраняются. Для каждой обои вводится общий затемняющий scrim, а элементы чата
остаются контрастными:

- `default`, `grid`, `waves`, `night` — нейтральный набор Signal Core;
- `aurora`, `paper` — выразительные дополнительные варианты;
- preview в выборе обоев отображает фрагмент реального интерфейса;
- настройка по-прежнему персональна и синхронизируется только между
  устройствами владельца.

### 5.7 Безопасность как отдельный визуальный сценарий

- Регистрация и подтверждения используют Signal Trace как индикатор шага.
- Успех, внимание и риск всегда включают текст, иконку и доступный статус.
- Устройства, e-mail, пароль, PIN и связанные аккаунты получают компактные
  action-поверхности с ясным уровнем чувствительности.
- Опасные действия не используют тот же вид, что обычные сохранения.
- Интерфейс не обещает E2EE или другие механизмы защиты, которых нет у
  конкретного сценария.

### 5.8 Адаптивная плотность

Добавляется локальное предпочтение плотности:

- **Комфортная** — по умолчанию, больше вертикального воздуха;
- **Компактная** — desktop-режим для длинных списков и больших экранов.

Это независимая настройка от уже существующего выбора режима отображения
(auto / desktop / tablet / mobile). На mobile всегда применяется комфортная
плотность.

## 6. Компонентные правила

| Компонент | Правило Signal Core |
| --- | --- |
| Button | Лайм — только primary CTA; secondary — спокойная tonal/outline поверхность; danger — отдельный контрастный вариант |
| Input | Плотная непрозрачная поверхность, видимый `focus-visible`, ошибка у конкретного поля |
| Navigation | Rail/side drawer с Signal Rail у активного пункта; mobile bottom navigation без тяжёлого стекла |
| Chat row | Цельная строка, Signal Rail у active, online Beacon, compact unread badge |
| Message bubble | Непрозрачные incoming/outgoing, чёткие нижние углы, действия поверх по hover/focus |
| Composer | Поднятая рабочая поверхность с лёгкой тенью; всегда отделён от обоев |
| Profile | Identity Beacon у аватара, AraChat ID в непрозрачном идентификационном блоке |
| Settings | Боковые/горизонтальные вкладки и цельные секции; security overview с семантическими статусами |
| Dialog/Menu | Единственные элементы с явной elevation и допустимым blur в Liquid Glass |

## 7. Реализация и порядок миграции

### Этап 1. Фундамент

1. Добавить семантические CSS-токены и сопоставить с ними текущие токены.
2. Сделать `comet` fallback-значением ThemeProvider и основной темой новых
   регистраций, не меняя сохранённые настройки пользователей.
3. Добавить провайдер плотности и селектор в настройки внешнего вида.
4. Усилить общие правила focus, reduced motion и наименования состояний.

### Этап 2. Оболочка и навигация

1. Перевести AppShell, desktop drawer и mobile navigation на Quiet Depth.
2. Добавить Signal Rail для навигации и активных строк диалогов.
3. Реализовать Focus Canvas на desktop/tablet без изменения маршрутов.
4. Добавить Identity Beacon в аватары чатов и профиля.

### Этап 3. Переписка

1. Перевести чат, composer и bubbles на chat-токены.
2. Добавить защитный слой обоев и preview, сохранив текущие варианты.
3. Уточнить ритм групп сообщений в пределах уже доступной DOM-разметки и
   сообщений; не менять серверную модель.

### Этап 4. Профиль, настройки, auth и public

1. Обновить identity-card, security overview, формы и опасные действия.
2. Включить Signal Trace в доступные статусные и onboarding-сценарии.
3. Согласовать public Comet с рабочим приложением без переноса маркетинговой
   декоративности в чат.

### Этап 5. Проверка

1. Production build через `npm run build:web`.
2. Проверка desktop, tablet, mobile и forced layout modes.
3. Проверка всех трёх палитр, шести обоев и сохранения настроек.
4. Клавиатурная навигация, focus-visible, контраст, reduced motion.

## 8. Риски и ограничения

- В репозитории один большой `global.css`; миграция должна добавлять
  переопределения и семантический слой постепенно, без массовой небезопасной
  перезаписи правил.
- Группировку сообщений нельзя корректно завершить только CSS, если разметка
  не несёт информации о соседних авторах и времени. На первом проходе меняется
  ритм существующих пузырьков; структурная группировка требует отдельной
  изолированной доработки ChatPage.
- Компактная плотность не синхронизируется с профилем: это локальное
  предпочтение конкретного устройства.
- Смена default-темы на Comet относится к новым/неопределённым настройкам;
  настройки старых аккаунтов и сохранённые значения не мигрируются принудительно.

## 9. Критерии готовности

1. Новая установка открывает Signal Core / Comet, а сохранённые Halo и Liquid
   Glass остаются выбранными.
2. Активные чаты и разделы используют Signal Rail; online и unread доступны не
   только по цвету.
3. На desktop/tablet доступен Focus Canvas, на mobile его нет.
4. Пузырьки и composer остаются непрозрачными и контрастными при всех обоях.
5. Настройки безопасности различают обычные, успешные и опасные действия.
6. Compact density не влияет на mobile и не конфликтует с layout mode.
7. Production build проходит; нет регрессии маршрутов и сохранения тем.

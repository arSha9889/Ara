# Nexus / N-Web/v1 — UI Kit и экраны приложения

## 1. Назначение

Документ фиксирует **UI Kit** и набор экранов для **Nexus (Nex) / N-Web/v1**. Он нужен как рабочая спецификация для дизайна и дальнейшей React-реализации Web Core.

Основание:

- `plans/architecture.md`;
- `plans/web-core-design.md`.

## 2. Принципы интерфейса

1. **Ясность важнее эффектов.** Пользователь должен понимать, что происходит на каждом шаге регистрации, входа, восстановления и общения.
2. **Мягкая технологичность.** Nexus выглядит современно, но не холодно и не агрессивно.
3. **Семейная безопасность.** Тексты, состояния и визуальные акценты должны вызывать доверие.
4. **Минимум перегруза.** Nexus ID показывается только там, где он реально нужен: в профиле, входе, восстановлении и добавлении контакта.
5. **Единая структура тем.** Nexus Halo, Nexus Orbit и Nexus Aurora меняют токены, но не меняют UX-логику.
6. **Mobile-first для PWA.** Auth-экраны, список чатов и чат должны быть удобны на телефоне.

## 3. Темы

В Web Core поддерживаются три темы. Все темы используют одну структуру экранов и компонентов.

### 3.1 Nexus Halo

Тема по умолчанию. Характер: мягкий, приватный, семейный, современный.

Фирменный мотив: **Halo Ring** — мягкий ореол вокруг активного чата, аватарки, выбранной темы, карточки Nexus ID и успешных действий.

Основные токены: `#F7F8FF`, `#FFFFFF`, `#151827`, `#0D1020`, `#151A2E`, `#F6F7FF`, `#6E5BFF`, `#46D9FF`, `#22C55E`, `#F6B73C`, `#EF476F`.

### 3.2 Nexus Orbit

Альтернативная футуристичная тема про связи, орбиты и персональное пространство.

Фирменный мотив: орбитальные кольца и линии связи вокруг аватаров, активных чатов и пустых состояний.

Основные токены: `#090B16`, `#12172A`, `#1B2340`, `#F5F7FF`, `#9BA3B7`, `#4B8BFF`, `#A66CFF`, `#4FFFD2`.

### 3.3 Nexus Aurora

Альтернативная мягкая светящаяся тема.

Фирменный мотив: мягкие градиентные пятна, aurora-подсветка активных элементов и плавные переходы состояний.

Основные токены: `#F7F8FF`, `#FFFFFF`, `#0E1020`, `#171B33`, `#7C5CFF`, `#58D7FF`, `#FF8FC7`, `#14142B`, `#697086`.

## 4. Базовые дизайн-токены

### 4.1 Типографика

Основной шрифт: **Manrope**.

| Стиль | Размер | Вес | Применение |
| --- | --- | --- | --- |
| `display` | 32–40 px | 700 | стартовый экран, крупные заголовки |
| `h1` | 28–32 px | 700 | заголовки auth-экранов |
| `h2` | 22–24 px | 700 | заголовки разделов |
| `body` | 15–16 px | 400/500 | основной текст |
| `caption` | 12–13 px | 400/500 | подсказки, статусы, время сообщений |
| `button` | 15–16 px | 700 | кнопки и основные действия |

### 4.2 Форма и размеры

- Карточки: радиус 20–28 px.
- Кнопки: капсула, радиус 999 px.
- Поля ввода: радиус 16–20 px.
- Сообщения: мягкие bubble/capsule формы.
- Аватары: всегда круглые.
- Минимальный touch-target: 44 x 44 px.
- Базовый шаг spacing: 4 px.

### 4.3 Состояния элементов

Каждый интерактивный компонент должен иметь состояния:

- `default`;
- `hover`;
- `active`;
- `focus-visible`;
- `disabled`;
- `loading`;
- `error`, если компонент принимает пользовательский ввод.

Фокус должен быть видимым с клавиатуры. Нельзя полагаться только на цвет: для ошибок нужны текст, иконка или изменение формы.

## 5. UI Kit

### 5.1 Button

Варианты:

- `primary` — главное действие на экране;
- `secondary` — дополнительное действие;
- `ghost` — тихое действие без тяжёлого фона;
- `danger` — удаление, выход, завершение сессии;
- `telegram` — вход или регистрация через Telegram.

Правила:

- на одном экране не должно быть больше одной визуально главной кнопки;
- loading-состояние блокирует повторное нажатие;
- disabled-состояние сопровождается причиной рядом с формой, если причина не очевидна.

### 5.2 IconButton

Используется для настроек, поиска, отправки сообщения, возврата назад, копирования кода.

Минимальный размер: 44 x 44 px. У каждой иконки должен быть доступный текст для screen reader.

### 5.3 TextInput

Используется для username, Nexus ID, display name, поиска и прямого ввода Nexus ID.

Состав:

- label;
- поле ввода;
- placeholder;
- helper text;
- error text;
- optional leading/trailing icon.

### 5.4 PasswordInput

Используется для создания и ввода пароля.

Особенности:

- кнопка показать/скрыть пароль;
- индикатор минимальной сложности;
- подсказка “от 5 до 30 символов”;
- отдельная ошибка для несовпадения повторного пароля.

### 5.5 PinInput

Используется для создания PIN и быстрого входа.

Правила:

- принимает только цифры;
- длина 4–8 цифр;
- показывает количество оставшихся попыток при входе;
- после блокировки показывает понятное объяснение и переход к другому способу входа.

### 5.6 CodeBlock

Используется для резервного кода восстановления.

Правила:

- код показывается группами по 4 символа;
- рядом есть кнопка копирования;
- экран должен явно предупреждать, что код показывается один раз;
- продолжение доступно только после подтверждения сохранения.

### 5.7 Avatar и AvatarPicker

В Web Core доступны только 20 встроенных аватаров: животные, люди и роботы.

Состояния аватара:

- обычный;
- выбранный;
- активный пользователь;
- пользователь онлайн, если presence уже доступен;
- placeholder.

Загрузка собственной аватарки не входит в Web Core.

### 5.8 ChatListItem

Состав:

- avatar;
- display name или username;
- preview последнего сообщения;
- время последнего события;
- индикатор непрочитанных сообщений, если готов в Web Core;
- состояние выбранного чата.

Не показывать Nexus ID в обычной строке списка чатов, чтобы не перегружать интерфейс.

### 5.9 MessageBubble

Варианты:

- входящее сообщение;
- исходящее сообщение;
- отправляется;
- отправлено;
- ошибка отправки;
- удалённое сообщение, если сценарий будет подключён позже.

Состав:

- текст сообщения;
- время;
- статус доставки на уровне Web Core;
- retry-действие при ошибке отправки.

### 5.10 MessageComposer

Состав:

- поле ввода сообщения;
- кнопка отправки;
- disabled-состояние при отсутствии соединения;
- helper/error text при ошибке отправки.

В Web Core composer поддерживает только текстовые сообщения. Вложения, голосовые сообщения и звонки проектируются позже.

### 5.11 EmptyState

Нужны варианты:

- нет чатов;
- пользователь не найден;
- нет истории входов;
- нет дополнительных активных устройств;
- нет интернет-соединения;
- чат не выбран на desktop.

EmptyState должен давать следующий шаг: найти пользователя, ввести Nexus ID, обновить соединение или вернуться назад.

### 5.12 LoadingState и ErrorState

LoadingState:

- skeleton для списка чатов;
- skeleton для сообщений;
- spinner для коротких операций;
- full-screen loading только при первичной загрузке приложения.

ErrorState:

- понятный заголовок;
- короткое объяснение;
- действие восстановления: повторить, изменить ввод, войти другим способом, открыть поддержку через Telegram-бот.

### 5.13 Modal и Sheet

Desktop/tablet: модальное окно по центру или боковая панель.

Mobile: bottom sheet или отдельный экран, если действие сложное.

Использование:

- подтверждение выхода;
- завершение сессии устройства;
- выбор аватара;
- preview темы;
- копирование и подтверждение резервного кода.

## 6. Экраны onboarding и авторизации

### 6.1 Стартовый экран

Цель: объяснить Nexus и предложить регистрацию, вход или восстановление.

Состав: логотип Nexus/Nex, короткий слоган, кнопка “Продолжить через Telegram”, кнопка “Войти по Nexus ID”, ссылка “Восстановить доступ”, переключатель RU/EN, декоративный мотив текущей темы.

### 6.2 Telegram-регистрация

Состав: Telegram Login Widget, пояснение про необязательность номера телефона, ошибка проверки Telegram подписи, действие “Попробовать снова”.

### 6.3 Выбор username

Состав: поле username, проверка доступности, подсказки по правилам, состояние “username занят”, кнопка продолжения.

Правила: минимум 3 символа, только латинские буквы и цифры `0–9`, запрещён оскорбительный и 18+ контент.

### 6.4 Создание пароля

Состав: поле пароля, повтор пароля, подсказка “от 5 до 30 символов”, индикатор минимальной сложности, предупреждение о безопасности, кнопка продолжения.

### 6.5 Создание PIN

Состав: поле PIN, повтор PIN, подсказка “от 4 до 8 цифр”, пояснение, что PIN действует только на этом устройстве, кнопка продолжения, действие “Пропустить”.

PIN можно пропустить при создании профиля и добавить позже в настройках.

### 6.6 Резервный код восстановления

Состав: резервный код группами по 4 символа, кнопка копирования, предупреждение, что код показывается один раз, подтверждение “Я сохранил код”, кнопка входа в приложение.

Переход дальше запрещён без подтверждения сохранения.

### 6.7 Вход по Nexus ID и паролю

Состав: поле Nexus ID, поле пароля, кнопка входа, ссылка “Войти через Telegram”, ссылка “Восстановить доступ”, ошибки неверных данных и превышения попыток.

### 6.8 Быстрый вход по PIN

Состав: приветствие пользователя, аватар или placeholder, поле PIN, счётчик оставшихся попыток, кнопка “Войти другим способом”.

## 7. Экраны основного приложения

### 7.1 Главный экран

Desktop/tablet: левая колонка со списком чатов, центральная область с выбранным чатом или пустым состоянием, верхняя панель с профилем, настройками, языком и статусом подключения.

Mobile: список чатов и личный чат работают как отдельные экраны; переход назад из чата возвращает к списку; поле ввода не должно перекрываться клавиатурой.

### 7.2 Список чатов

Состав: заголовок, поиск по username, прямой ввод Nexus ID для создания личного чата, список личных чатов, пустое состояние, индикатор последнего сообщения, базовый индикатор непрочитанных сообщений, если готов в Web Core.

### 7.3 Личный чат 1-на-1

Состав: заголовок чата, аватар и имя собеседника, список сообщений, поле ввода, кнопка отправки, состояние отправки, состояние ошибки отправки, автопрокрутка к новым сообщениям.

В Web Core чат поддерживает только текстовые сообщения.

### 7.4 Профиль

Состав: аватар, display name, username, Nexus ID, необязательный номер телефона, настройка публичного отображения номера телефона, язык интерфейса, текущая тема дизайна.

Nexus ID показывается только в профиле и в сценариях, где он нужен для входа, восстановления или добавления контакта.

### 7.5 Настройки безопасности

Состав: смена пароля, регенерация резервного кода, управление PIN, список активных устройств, история входов, завершение отдельных сессий, завершение всех сессий кроме текущей.

### 7.6 Настройки внешнего вида

Состав: выбор темы дизайна, карточка Nexus Halo “по умолчанию”, карточка Nexus Orbit “орбитальная тема”, карточка Nexus Aurora “мягкое сияние”, preview выбранной темы, сохранение выбранной темы в профиле.

Тема применяется без перезагрузки страницы. Если тема не загружена или повреждена, приложение возвращается к Nexus Halo.

## 8. Адаптивность

### 8.1 Desktop

- двухколоночная структура;
- список чатов слева;
- чат справа;
- настройки открываются отдельным экраном, модальным слоем или боковой панелью;
- ширина списка чатов должна быть стабильной и не прыгать при смене состояния.

### 8.2 Tablet

- при достаточной ширине используется двухколоночная структура;
- при узкой ширине используется mobile-поведение;
- touch-targets остаются не меньше 44 x 44 px.

### 8.3 Mobile / PWA

- список чатов и чат — отдельные экраны;
- auth-экраны помещаются в одну колонку;
- важные действия находятся в зоне большого пальца;
- поле ввода сообщения не перекрывается клавиатурой;
- стартовый экран и auth-flow должны работать в браузерах iOS и Android.

## 9. Доступность

- Все интерактивные элементы доступны с клавиатуры.
- Для focus-visible используется заметный контур или glow.
- Ошибки сопровождаются текстом, а не только цветом.
- Иконки без текста имеют aria-label.
- Контраст текста должен оставаться читаемым во всех темах.
- Кнопки и поля не должны быть меньше 44 x 44 px на touch-устройствах.

## 10. Локализация

Интерфейс поддерживает русский и английский языки.

Правила:

- строки не зашиваются внутри компонентов;
- кнопки и ошибки должны иметь ключи локализации;
- layout должен выдерживать более длинные английские и русские фразы;
- технические ошибки переводятся в понятные пользовательские сообщения.

## 11. Обязательные состояния

### 11.1 Пустые состояния

- нет чатов;
- чат не выбран;
- пользователь не найден;
- нет истории входов;
- нет дополнительных активных устройств;
- нет интернет-соединения.

### 11.2 Ошибки

- неверный Nexus ID или пароль;
- Telegram Login Widget не прошёл проверку;
- username занят;
- username содержит недопустимые символы;
- PIN введён неверно;
- PIN заблокирован;
- резервный код неверный;
- превышено количество попыток;
- WebSocket отключён;
- сообщение не отправлено.

### 11.3 Загрузка

- первичная загрузка приложения;
- проверка username;
- вход и регистрация;
- загрузка списка чатов;
- загрузка истории сообщений;
- сохранение настроек;
- переключение темы.

## 12. Что не входит в UI Kit Web Core

В Web Core не проектируются как готовые компоненты:

- групповые чаты;
- каналы;
- вложения;
- голосовые сообщения;
- аудиозвонки;
- демонстрация экрана;
- видеозвонки;
- загрузка собственной аватарки;
- полноценные семейные экраны;
- полная E2EE-настройка устройств.

Компоненты должны быть расширяемыми, но нельзя усложнять Web Core ради будущих функций.

## 13. Definition of Ready для дизайна и реализации

UI Kit и экраны считаются готовыми к реализации, когда есть:

1. Макеты стартового экрана, auth-flow, списка чатов, личного чата, профиля и настроек.
2. Desktop, tablet и mobile-варианты ключевых экранов.
3. Компоненты Button, Input, PinInput, CodeBlock, Avatar, ChatListItem, MessageBubble, MessageComposer, EmptyState, ErrorState, LoadingState, ThemeSwitcher.
4. Состояния hover, active, focus-visible, disabled, loading и error.
5. Preview-карточки тем Nexus Halo, Nexus Orbit и Nexus Aurora.
6. RU/EN-тексты для основных действий и ошибок.
7. Проверка, что Nexus ID не отображается постоянно на главном экране.
8. Проверка, что PIN не описывается как пароль от аккаунта.
9. Проверка, что резервный код восстановления объяснён простым языком.

## 14. Итоговое решение

Для N-Web/v1 принимается единый UI Kit с темой **Nexus Halo** по умолчанию и альтернативными темами **Nexus Orbit** и **Nexus Aurora**.

Первый набор экранов включает onboarding, регистрацию, вход, восстановление, главный экран, список чатов, личный чат, профиль, настройки безопасности и настройки внешнего вида.

Реализация должна идти через дизайн-токены и переиспользуемые компоненты, без дублирования экранов под разные темы.
